# Schedule

Bot’s More menu opens task history. The page has one h1, the app's location heading "Schedule" (예약), named as the page header and the sidebar row are; it takes focus when Bot's Scheduled tasks opens the page. Active and All filters, task details, run readers, linked evidence and notifications use the same saved task and run IDs. Focusing a control below the fold in a run scrolls it into the reader. A run's answer renders as the same card as in Chat, inside the run's own execution scope: its citations, links and workspace files open beside the briefing's own chat, which the Chat tab shows first (`useAppOpen`'s `openIn`), and a conflict card offers See on the Map. A briefing's reader shows what changed in the Map, the followed assets it read (by the names they were followed by) and Looking ahead (due Journal checks, the next run and skipped tools); it carries no asset deltas, results or alerts. A task's detail offers Pause or Resume (Turn on for a proposed task), Run now and, for a custom task, Delete after a confirmation that says its run history and the run sessions the user never wrote in go with it, while sessions the user wrote in stay in Research sessions and what it saved to Memory stays; these call `scheduled_task_set_status`, `scheduled_task_run_now` and `scheduled_task_delete` directly, so stopping a recurring model run never needs a model call. The briefing is turned off rather than deleted and a completed one-time task cannot be resumed. A failed last run says why beside those controls. A run is worded by its task's kind: a briefing's run is a briefing ("Couldn't finish this briefing", "Preparing your briefing…"), any other task's is scheduled research ("Couldn't finish this scheduled research", "Running this research…"). A failure with no known reason is said by that title alone, with its Details. A failed run's reader says why and offers Run now, which runs its task once more (`scheduled_task_run_now`) and shows the task, where the new run appears; reloading would only show the same failure, so Try again is kept for a reader that could not load. A custom task's prompt sits under a Prompt (요청 내용) label, and is left out when it only repeats the title. The Active and All filter appears once a task exists. Bot can change the built-in briefing’s days and time or a custom task’s time or prompt. Each detail names the available changes. Its Ask Bot link drafts the request in the composer when the shell provides one. The list's footer ("tell Bot what you want and when") has the same link, which opens Bot with its composer focused. A clear request registers immediately and returns the cadence and next execution time. A research session hands the request to its own Bot and stays open.

The scheduler runs briefings and custom tasks. An alert is a custom task whose prompt states the condition and evidence to check. A successful check that finds nothing to report can call `schedule_quiet` to keep its run in history without a Bot post or inbox entry; the task's Runs list marks it "Nothing to report" (보고할 내용 없음) beside its time, with its summary, and never as unread.

Schedule is where a task's runs are listed: task, then its runs, newest first, then a run's reader, whose Continue in Chat opens the run's own session. Those sessions are not listed under Research sessions until the user writes in one ([run sessions](../runtime/scheduled-runs.md#scheduled-chats)), so a daily task does not fill the sidebar; one nobody wrote in goes with its run when the run leaves the 50-run history. Continue in Chat reads the chats again first, so a reader opened before its session went says "This run's session was removed." (이 실행의 세션은 삭제되었습니다.) in place of the button and reads the history again instead of opening an empty session.
