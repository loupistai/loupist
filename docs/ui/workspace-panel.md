# Workspace panel

The panel holds a conversation’s **Chat materials** (대화 자료), including **World for this chat**, Evidence, Work, browser and workspace-file readers. It opens from "Open chat materials" on the activity sheet's In use tab ([activity sheet](chat-composer.md#activity-sheet)), from ⌘\, and from answer links, beside the current chat without changing chats or the composer's draft, files, pins, as-of date or selected artifact. **World** (월드) and **Lens** (렌즈) open as full pages in the main area from their sidebar rows, ⌘3/⌘4, the command palette and knowledge deep links ([sidebar](sidebar.md), [World and Lens](map-lens.md)). Explicit answer links, citations, artifacts and workspace files open in the panel. A Lens page opened from chat (a `lens:` link, a learned page's title, a saved Lens change) always opens in the Evidence reader; only that reader's Open in Lens goes to the Lens page. A principle has no page to read there, so its View opens on {Loupist}’s Lens. The panel tab’s "Open World →" and Expand open the selected name in World. "Back to chat" returns to the panel as it was. A tab opened from chat leaves focus where it was, and one polite live region in the app shell says "Opened {title} in the panel" in the interface language, a Lens record's title included.

A new profile starts with the panel closed. A saved layout restores through Rust's bounded workspace UI state. A dock choice is stored there with the panel dimensions. Narrow windows retain the existing focus-trapped sheet instead of forcing a split that cannot fit. The retained readers stay per-chat bounded typed references.

The panel lists work created in the open conversation and restores only bounded references. It does not open itself for an empty state or by moving keyboard focus. The first names a chat saves open the World tab beside that chat when the window is at least 1280px wide and the panel is not the narrow sheet. If the user closed the panel in that chat, it stays closed. If they are already reading another tab, the World tab is marked instead of taking over.

The Evidence reader explains extraction warnings in the interface language, including when page navigation surrounds the saved passage. Unrecognized warning codes show a general source limitation.

Readers preserve selection, focus and scroll through navigation. Workspace panel
preferences store bounded references, not reader bodies; restoration repeats
ownership checks. A stored file that is too large, malformed, of an older shape or
fails validation reads as absent, so the next save replaces it; I/O failures still
surface as errors and never overwrite a good layout. The panel has one Work tab that
lists this conversation’s published charts, tables and documents (Rust `chat_artifact_list`) together with workspace files the host confirms the Loupist wrote. Rows are ordered by the latest write or revision. A file opens in Files. The list begins with "Preparing" rows for charts still streaming;
an item opens inside the tab under a status row with its title, a "Version n ▾" menu of the revisions Rust keeps (`artifact_versions`, newest first with dates) and the shown revision's date, and reads from its own chat. Opening an item from the keyboard moves focus to All work, and All work returns it to that item's row; a row whose read fails keeps focus under the error. Choosing an earlier version reads it by `revision_id` read-only; "Restore this version" asks once, then `artifact_restore` appends it as the newest revision and the panel follows it, while answers keep the revisions they showed. Charts dock at the bottom
and reading content at the side by default; using Dock records the choice per kind
(`dock_by_kind`), and the dock changes only when a different kind comes on screen. "Always dock at side" (or "at bottom", naming where the panel is) in the panel menu stores the current placement for every kind (checked while every kind docks there); turning it off clears the choices back to the defaults. A closed panel stays closed when background work finishes; document arrivals are retained in Work, while charts and tables render inline. Closing it marks that chat `dismissed` in the Rust-validated workspace UI state until the user opens it again. Content that arrives while
the user is working in the panel marks its tab with a dot instead of switching. On a conversation the page header carries two split buttons beside Activity, Split top and bottom and Split left and right: each opens the panel docked there, the one in use reads pressed, and pressing it again closes the panel. The page header and its buttons stay visible while the panel is open; the panel shows only on a conversation, so a World, Lens or Schedule page hides it until the conversation is back. Below 1060px the sheet is positioned in the stage under the page header, so it does not cover them. When the stage is at least 840px wide a side sheet leaves a strip of the chat, and the chat wraps into that strip so a line is not sliced by the sheet. Under 840px of stage the sheet covers the whole stage, because a strip that narrow cannot be read. Close on the panel header, ⌘\, Escape, and the narrow sheet's backdrop close it; in the browser's address field Escape first puts back the page's address, and in the Files filter it first clears the filter. Opening it from the keyboard moves focus to Close. Tabs and Add stay on the tab
bar, and the Add menu stays above the browser address field. The tab strip is light underline tabs on the panel background: the selected tab shows a 2px underline under its content and no fill, a hovered tab gets a soft rounded background, and one hairline separates the fixed World, Evidence and Work tabs from reader tabs only when reader tabs exist. A page tab keeps its title, up to 220px, instead of shrinking until a short host is cut; the tab row scrolls the selected tab into view when World, Evidence and Work take the rest of the row. Expand, Dock and the Always dock choice live in one panel menu on the docked panel; the
narrow overlay offers Close only. Expand in the World tab opens World
on the name selected in the chat’s view of World; on any other tab it covers the main area beside
the sidebar with that tab in one reading column and "Back to chat" (Esc returns first,
the next Esc closes the panel; the chat underneath is inert). Closing the panel
returns focus to the page header's Activity button when the control that
opened it is no longer in that chat. Leaving the
reading column returns focus to the panel menu.

A long page title truncates inside its 220px tab, before Close.

A completed `run_python` progress item carries `writtenPaths` for up to 32 successfully copied workspace files. These paths survive in the session history. Deleted files, write conflicts and failed runs are excluded.

### Reading a workbook

Files shows workbook values in a read-only grid with column letters and the original row numbers. Visible sheet tabs follow workbook order. Hidden sheets appear at the end as dimmed tabs with a hidden label. The caption names omitted charts, images and formatting and gives the displayed and total row counts for a truncated preview. While the host reads the workbook, Files shows a localized loading message. Preview refusals give their reason and leave Open available. Formula cells with a saved value have a corner mark. Formula cells awaiting calculation show an em dash, with a tooltip explaining how to calculate them.

The Files panel can request `workspace_workbook_read` with a workspace-relative XLSX or XLSM path and an optional zero-based sheet index. The host reports `checking_file` and `reading_sheet` while the request is pending. It returns sheets in workbook order, including hidden sheets, and defaults to the first visible, non-empty worksheet. Hidden worksheets and chart sheets remain listed. An explicit request for either returns `unsupported_sheet`. The projection reports one-based starting coordinates, used row and column counts, typed display cells, truncation and omitted features. Merged cells show their value at the top left. Formula cells show only their saved value and carry a formula flag even when that value is missing. Cells retain their number format when present. Charts, images, comments, visual styling and macros are omitted. XLS, XLSB and encrypted workbooks cannot be previewed.

The host checks the path against the selected workspace, opens it without following links, and reads up to 8 MiB. Before starting Python it checks the ZIP headers, expanded lengths, a 200:1 per-entry ratio, and limits of 4,096 entries, 32 MiB per entry and 64 MiB expanded. A private WASI worker receives one read-only workbook and a fixed host script. It uses openpyxl in read-only, cached-value mode with VBA and external links disabled. The preview admits up to 64 sheets, shows up to 200 rows × 40 columns, limits cell text and format strings to 1,024 characters, and reserves 48 KiB for row data. Time and memory limits are 60 seconds of guest execution and 512 MiB of guest memory; cold compilation has a separate host deadline. A dedicated preview lane retains 16 successful projections in memory by content digest and sheet. It operates independently of chat runs, agent worker admission, Activity, receipts and file writeback.

### Opening a document in its application

Files offers Open alongside Show in file manager for workbooks and for other admitted documents without a preview. Open names the default application when the host can resolve it and stays disabled until the launch returns. A launch failure names the application reported by the open request, displays the system reason when available and leaves Show in file manager in the error message.

On file selection, the Files panel can call `workspace_document_handler` to check admission and read the default application name before the user opens the file. The lookup uses the same workspace policy and document checks as the open action. It returns `allowed` with the nullable application name or `refused` with the typed reason. It only reads the file and asks macOS for its default handler. The open action checks admission again.

An explicit Files action can submit `workspace_document_open` with a Loupist ID and workspace-relative path. The host resolves the workspace again, refuses links, reparse points, directories and application bundles, and checks the opened regular file against the permitted document extensions and content. The allowed types are XLSX, XLSM, XLS, CSV, TSV, DOCX, PPTX, PDF, PNG, JPG/JPEG, GIF, WebP, SVG, TXT, MD and JSON. HTML remains a source preview. A refused request returns a typed reason. On macOS the host hands a file-reference URL for the admitted inode to LaunchServices and includes the default handler’s localized display name when available. Linux sends the checked descriptor to the desktop OpenFile portal. Windows keeps the file and parent directories pinned during dispatch to the system handler. Linux and Windows return a null application name. A `requested` response records dispatch to the operating system. On macOS the host waits for the system open command’s exit status. A launch failure returns `handler_unavailable` with the default application name and system reason when available. Files displays the failure with Show in file manager. The command is available to the renderer only.
