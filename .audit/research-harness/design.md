# Autonomous research feedback

## Goal and acceptance

An ordinary research conversation can retain source-bound checks, autonomously form a candidate Lens after distinct investigations, and use its exact revision in a later investigation. The user does not have to teach a method or configure an ontology. A candidate opportunity is a dated hypothesis with supporting evidence, counterevidence, a falsifier, and a qualified exposure identity. This work does not establish investment alpha.

Keep the current single Pi turn and one Rust Memory writer. Do not add subagents inside the product, automatic research restarts, or permission expansion. Existing silence watchdogs are not spend caps.

## Synthesis decision

Candidate A is the base. The independent gpt-6.1-terra judge scored A 4/5/5/4/5 and B 4/5/4/3/5 for authority/privacy, bounded lifecycle, UX, maintainability, and falsifiable future use. Both candidates converged on the current Pi loop. A has the smaller public payload and requires evidence from two distinct committed investigations.

Use A's dedicated immutable experience table. Candidate B's independent research rows avoid a table but complicate the bounded research-note scan and body decoding. A separate owner with explicit integrity and erasure integration keeps those user-facing reads stable. Do not add B's separate schema-read tool or duplicate opportunity prose in the feedback payload. Both candidates' distinction between method retention and measured usefulness remains binding.

## Caller contract

Extend the existing note_save with optional researchReview. It contains question, one to six checks, and optional nextCheck. A check contains question, disposition (supported, mixed, not_supported, unresolved), finding, acknowledged evidence references, optional exact methodRead, and limitation. This is a model assessment, never a success score or user judgment. Bound strings and lists at admission. Non-unresolved checks need evidence; unresolved checks must identify a gap. References must already be admitted inputs of the enclosing note, owned by this turn and Loupist.

Resolve references to immutable admitted Source, World, and Lens snapshots during the existing completed-turn Memory transaction. Preserve exact Lens revisions. Save one immutable experience per Loupist and turn, independent of replaceable working notes. An identical repeat is idempotent; a conflicting repeat refuses. The ordinary note remains the visible research document. No raw conversation or hidden reasoning is retained in experience data.

Use a dedicated knowledge_research_experiences table and a typed body owned by knowledge/research. Include its digest in integrity checks and its rows in Memory erasure and Loupist deletion. Exclude experiences from sharing unless an explicit existing package rule admits them. Experience snapshots must not silently survive an erasure request. Follow the repository's existing pre-1.0 compatibility contract: Knowledge schema becomes version 6, earlier folders are refused with the existing typed state and left intact, with no automatic migration or deletion. This compatibility limit must be explicit in documentation and the PR.

The user-facing reset of learned Memory also clears this Loupist's agent experiences and frozen learning-review input/output. It keeps the reset's existing user/shared ownership rules. Re-enabling learning or graph processing reconsiders retained eligible experiences through the same queue and rate limits; it does not require an unrelated new turn to wake the queue.

## Learning contract

Extend the existing queue and tool-free learning reviewer. Two eligible completed experiences from distinct turns admit a review even without five new World claims. Keep the World-drained gate, cooldown, daily cap, one inference attempt, principle checks, stale-head proposal behavior, and uncertain-attempt quarantine.

Use a separate experience watermark; make world_job_id optional rather than fabricating a graph job. Freeze both watermarks at admission. New experiences arriving after admission remain for a later review. Paid failure and uncertain completion consume the admitted range and do not retry automatically.

Keep all current principles in the existing bounded input, then bounded recent experiences and relevant claims. Output may cite evidenceObservationIds alongside evidenceClaimIds. Every cited ID must belong to the frozen input and be deduplicated. Publication requires either the existing two distinct claim basis or observations from two distinct committed turns with at least one eligible retained original Source in each cited turn. This validates provenance, not truth or usefulness. New autonomous methods remain candidates.

Published Lens changes retain deduplicated exact Source references from the cited observations so the existing saved-basis reader can open their originals. The host resolves Source object IDs and reuses existing revision/span authorization in the publication transaction. These references carry no new read receipt. A removed or no-longer-retained source version, or a basis beyond the existing reference limit, defers publication instead of substituting current evidence.

Memory off and read-only do not retain experiences. Recheck saving/learning controls, shared-content taint, and ownership at commit and publication. Historical/as-of experiences do not trigger current learning. Stop or failed completion publishes no staged note, experience, Source, or learning admission.

## Schema and experience

Derive bounded World vocabulary from the same active schema used by extraction. Include meanings, signatures, revision/digest, and issuer/instrument caution in the Chat Memory envelope and context digest. Avoid a hand-maintained second ontology. Omit a personal extension updated after an as-of cutoff and explicitly identify unavailable historical definitions. Memory off omits personal schema. A cutoff is not a claim that current bundled application vocabulary existed historically.

The existing composer, receipt, Lens reader, and learning notification are sufficient. Correct copy that requires user teaching or equates a delivered Lens with successful use. Show autonomous methods as candidates or not independently evaluated using real provenance. No quality score, intelligence meter, or new settings screen. Keep English/Korean, keyboard, narrow-width, reduced-motion, and native WebView behavior covered.

## Verification and claim limits

Prove admission/refusal at the real broker boundary; exact snapshot and revision readback; working-note replacement survival; idempotency; rollback/Stop; Memory off/read-only/taint; as-of; erasure/integrity; pending-review coalescing; unknown output IDs; settings changes; stale Lens heads; and no paid automatic retry.

Exercise production learning with two ordinary research experiences and a later fresh held-out question. Inspect actual exact Lens delivery and method application, plus a question outside applicability. Use existing A/B/C/D Lens comparison for any quality claim. Structural test success proves a working retention/reuse path only. Report live evaluation limitations honestly.

Run scripts/verify.sh, affected Linux source checks, and macOS WKWebView checks for changed views before PR handoff. Commit and push the task branch and open an attached PR. Do not merge or release.
