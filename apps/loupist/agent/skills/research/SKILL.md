# Research

Identify the question, entity, cutoff, and evidence that could change the
answer. For multi-step work, keep a short plan around those unknowns and a
stopping condition tied to the requested outcome.

Choose methods for the unresolved parts of the question. Available optional
Skills can help with a substantial valuation, comparison, or test; combine
the results around the research question without running a fixed menu.

For a thesis review or catalyst update, read
[thesis review](references/thesis-review.md). Actively seek strong
counterevidence and observable invalidation conditions. For move attribution,
establish the move and time window before testing explanations. Temporal
association alone does not establish causation.

Before acquiring new material, discover relevant World relationships, retained
originals, methods, and research notes. Exact-read useful matches and the complete
Lens documents before applying them. Use the turn's World vocabulary to interpret
types and relationship direction. A graph path is a research lead; read the
originals behind decisive links. Keep dated priors distinct from fresh evidence.

Test the weakest important link and the strongest competing explanation. A
negative result or missing evidence can be the useful outcome. Stop when the
supported answer and material gaps are clear; do not extend the work merely to
create more Memory.

When looking for opportunities, distinguish the organization or project from the
specific exposure. Verify the instrument, exchange, currency, share class,
maturity, or contract where relevant before comparing price, yield, or valuation.
If an identifier is unresolved, report the business hypothesis and that gap.
For each supported candidate, explain the mechanism, dated supporting evidence,
counterevidence, and an observable condition that would overturn it. A plausible
connection is a candidate hypothesis, not demonstrated excess return. No supported
candidate is a valid result.

With saving enabled, retain decisive originals with `source_save` and finish a
substantive investigation with `note_save`. Update the working note and include
`researchReview` when the investigation produced checks worth reusing. Record the
research question and each check's question, disposition, finding, evidence,
limitation, and optional next check. Use `supported`, `mixed`, `not_supported`, or
`unresolved` to describe your assessment. An unresolved check must explain what is
missing. These assessments do not verify a method's effectiveness.

Each check's `evidence` must use acknowledged Source or World references also in
the note's `sourceReads` or `worldReads`. If a method guided that check, set
`methodRead` to its exact read reference and include it in `lensReads`. A fetch or
capture ID is not a retained Source reference. Do not invent receipt IDs or save
the same investigation twice to trigger learning. The host can review completed
experiences for reusable candidate methods without a user lesson. That review
does not extend this conversation; finish the answer instead of waiting for it.

Follow the common Memory controls. With saving off, give the answer without
retaining a review. Use `journal` only for the user's explicitly stated judgment,
never for your own candidate or a proposed lesson. A tool acknowledgment is staged;
only a completed Memory commit establishes retention.

Lead with the supported answer, then decisive evidence, competing explanations,
assumptions, and remaining gaps. Link the exact sources and methods used.
